## 같은 소스 확인 절차

1. 기존 작업 폴더·변경·기록을 보존합니다. 별도 빈 폴더에 GitHub 저장소를 clone하고 위 후보 커밋을 detached HEAD로 선택합니다. `git rev-parse HEAD`로 40자리 커밋을 확인합니다. 다운로드·소스 선택은 실행 성공이 아닙니다.
2. 새 폴더에서 Node·Git·PowerShell 버전과 운영체제·브라우저 환경을 확인합니다. 새 환경은 우선 같은 PC의 별도 checkout이며 다른 물리 PC 시험으로 기록하지 않습니다.
3. [학생 실행 설명서](STUDENT_RUNBOOK.md)의 실행 절차를 새 checkout의 `on-client` 위치에 적용합니다. 외부 npm 의존성이 없으므로 기본 실행에 설치 명령을 추가하지 않습니다. 기존 서버와 같은 포트를 중복 사용하지 않습니다.
4. 기본 실행·브라우저·종료·재실행을 차례로 확인하고 13~21단계를 같은 커밋에서 점검합니다. demo는 예제 표시 점검으로 따로 기록하며 운영 연결 성공으로 계산하지 않습니다.
5. 사용자가 보고한 결과만 아래 표에 기록합니다. 후보 확인 뒤 기록을 커밋할 때 코드 변경 여부를 대조합니다. 문서만 바뀌었더라도 최종 제출 커밋을 새 checkout에서 다시 받아 실행·재실행하여 최종 인수인계 진술과 연결합니다. 재확인하지 않은 기능은 최종 커밋 실측으로 승격하지 않습니다.
6. 공식 22단계는 코드·문서·학생 진술의 일관성 검토입니다. 서버 AI가 명령을 실행했다거나 운영 연결을 인증했다고 적지 않습니다. 공식 단계 제출은 사용자가 직접 수행합니다. 공개 저장소는 주소와 커밋을 직접 제출하며 원문 JSON은 서버가 읽을 수 없는 비공개 커밋일 때 안내에 따라 선택합니다.

## 필요한 파일과 설정

Git checkout에 포함되는 것은 실행 소스·제공 모듈·학생 함수·학생 문서·값 없는 [설정 견본](../.env.example)입니다. 기본 실행은 인증 파일이나 실제 자격정보를 필요로 하지 않습니다. 앱은 .env 파일을 자동으로 읽지 않습니다. 필요 프로그램·지원 버전·정상 로그·브라우저 주소는 학생 실행 설명서와 `on-client/package.json`, `tools/start-alekov.ps1`을 대조합니다.

실제 NativeHost·SDP·AI·집행 연결은 해당 PC·프로젝트에 맞게 담당자가 발급·확인해야 합니다. 기존 폴더의 자격·승인 저장소·인증서·토큰·개인키를 새 폴더에 복사하지 않습니다. 실제 값을 문서·Git·원문 제출물에 넣지 않습니다. 운영 패키지 조회 대상과 공개 허용 목록도 임의로 확대하지 않습니다.

## 미해결 사항과 인수인계 제한

현재 실제 SDP·XDR·NativeHost·AI 설명·조치 집행 및 효과 관측·OSV 외부 조회는 새 환경에서 미확인입니다. 실제 학생 계정 집행 연결은 아직 준비되지 않았습니다. 패키지 조회가 not_configured라면 설정 미완료로 기록하며 취약점 없음으로 바꾸지 않습니다. 실제 집행 결과가 남아 있으므로 릴리스는 검증 중이고 v1.0이 아닙니다.

운영 승인·집행·외부 데이터 백업/복원·다른 물리 PC 검증은 학생 코드 검토나 이번 같은 PC의 새 checkout 재현으로 인증하지 않습니다. 공식 AI 통과와 학생 진술의 실행 결과도 별개의 근거입니다.
