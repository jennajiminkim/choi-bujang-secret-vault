# nævis 완성본 시연 안내와 확인 근거

작성일: 2026-11-03 · 시각 기준: 한국 시간(KST, UTC+09:00)

## 1. 이번 시연의 범위

nævis는 PC 상태와 전달받은 계정·기기·세션·보안 기록을 구분해 보여 주는 프로젝트 폴더 실행형 앱이다. 포장 명령은 실행하지 않았으며 이 안내에서도 실행하지 않는다. 기존 프로젝트·이전 제출물·main 브랜치를 지우거나 이동하지 않는다.

관제 대시보드형의 요약 카드 네 개는 사용자·현재 기기·현재 세션 세 개를 위쪽 같은 너비로, 계정·기기·세션 자료 연결 한 개를 그 아래 전체 너비로 배치했다. 추이·기록은 기존 보안 기록 메뉴에서 보여 준다. 모든 기능을 한 화면으로 옮긴 구성은 아니다. 제공 메뉴와 제공 PC 조회 영역을 유지한다.

- 저장소: https://github.com/jennajiminkim/choi-bujang-secret-vault
- 작업·제출 브랜치: `naevis-dashboard`
- 이 문서 작성 기준 앱 커밋: `fe98aa848a1ad8739baa6d001f638a02ec44ec9f`
- 기준 커밋 화면: https://github.com/jennajiminkim/choi-bujang-secret-vault/commit/fe98aa848a1ad8739baa6d001f638a02ec44ec9f
- 위 번호는 사용자 `git rev-parse HEAD` 출력과 GitHub 브랜치 조회가 일치한 번호다. 이 문서를 추가한 최종 제출 커밋 번호는 별도로 확인해야 한다. 문서 자신의 커밋 번호를 미리 적지 않는다.
- 최종 디자인에서 기록 조회 → PC 실측 → SDP 진단의 시연 절차를 수행한 사용자 보고와 아래 근거를 확인했다. 재조회·필터 변경 후 전체 복원은 사용자 보고이며, PC 실측은 캡처, SDP 진단은 텍스트 보고에 근거한다. AI가 전체 과정을 실시간으로 직접 관찰한 것은 아니다.

| 구분 | 기능·파일 | 시연에서 설명할 점 |
|---|---|---|

| 학생 | 같은 파일의 기록 다시 조회·대기·실패·복구 안내 | 학생 기록 영역만 수동으로 갱신한다. 제공 PC 실측과 SDP 도움정보를 함께 갱신하는 버튼이 아니다. |

디자인 변경은 학생 파일 두 개에 한정했다. `public/app.js`, `public/style.css`, `src/` 서버와 실행 도구·인증 설정은 디자인 작업에서 수정하지 않았다. 과거 시작 틀 업데이트에 따른 변경과 이번 학생 디자인 변경을 혼동하지 않는다.

## 3. 실행 준비와 명령

사용자가 확인한 환경은 동일 Windows PC, Node.js `v24.19.0`, 시작 틀 0.2.21이다. 공식 Node ZIP을 프로젝트 밖에 풀어 현재 PowerShell의 PATH에만 적용해 사용했다. 새 창에는 임시 PATH가 이어지지 않는다. 환경 준비가 필요하면 [실행 안내](NAEVIS_QUICK_START.md)와 [상세 안내 13장](NAEVIS_DASHBOARD_GUIDE.md#13-5일차-본인의-별도-폴더-재현과-안내-보완)을 따른다. 기존 Node를 삭제하거나 버전 검사를 우회하지 않는다.

시험·시연 폴더:

`C:/Users/Administrator/Desktop/naevis-day5-repro/on-client`

원래 작업 폴더:

`C:/Users/Administrator/AppData/Local/ALEPH/Workbench/projects/on-client`

Git 백업 저장소 루트:

`C:/Users/Administrator/Desktop/naevis-dashboard-save`

세 폴더를 구분한다. 이번 시연은 재현 폴더에서 한다. 백업 저장소에 최신 커밋이 있다고 해서 재현 폴더의 Git HEAD도 자동으로 갱신되는 것은 아니다. 원래 작업 폴더는 Git 저장소가 아니다.

이미 이 앱이 실행 중이면 그 서버 창을 계속 사용한다. 새로 실행해야 한다면 기존 이 앱 서버 창에서 Ctrl+C로 종료하고, Node 환경을 준비한 같은 창에서 다음 블록을 실행한다. 다른 프로세스를 임의로 종료하지 않는다.

```powershell
& {
    $ErrorActionPreference = 'Stop'
    Set-Location "$env:USERPROFILE\Desktop\naevis-day5-repro\on-client"
    $version = node --version
    if ($LASTEXITCODE -ne 0 -or $version -ne 'v24.19.0') {
        throw "현재 Node 버전: $version. v24.19.0 환경을 먼저 준비하세요."
    }
    Write-Host "실행 폴더: $((Get-Location).Path)"
    Write-Host "Node 버전: $version"
    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
}
```

「케셰브가 켜졌습니다」가 표시되면 **그 창을 열어 둔 채** 브라우저에서 http://127.0.0.1:5189/ 을 연다. 서버 응답은 SDP·AI 연결 성공을 뜻하지 않는다. 같은 앱을 중복 실행하지 않는다. 종료는 서버 창의 Ctrl+C다.

사이트 연결 불가가 나오면 새로고침만 반복하지 않는다. 별도 PowerShell에서 다음 한 줄로 응답을 확인하고, 실패하면 서버 창의 마지막 메시지·폴더·Node 버전을 기록한다.

```powershell
Invoke-WebRequest -Uri 'http://127.0.0.1:5189/' -UseBasicParsing -TimeoutSec 5 -ErrorAction Stop | Select-Object StatusCode
```

디자인 적용 중 실제로 연결 실패가 있었고 이 명령으로 응답 실패가 보고됐다. 재실행 안내 후 화면이 다시 나타났다. 당시 서버가 종료된 정확한 원인은 확보하지 못했다. 새로고침이나 디자인 코드가 서버를 종료했다고 단정하지 않는다.

## 4. 핵심 기능 세 가지의 시연 순서

먼저 보호 현황에서 밝은 화면과 요약 카드 네 개(상단 세 개 + 하단 한 개)를 짧게 보여 준다. demo 표시는 유지한다. 이어서 다음 세 기능을 순서대로 시연한다.

| 순서 | 직접 할 행동 | 화면에서 확인할 결과 | 설명할 문장 |
|---|---|---|---|
| 1. 보안 기록 | 보안 기록 → 학생 「기록 다시 조회」. 목록이 나타나면 필터를 한 번 바꾸고 전체로 복원. 사건 상세 열기 | 갱신 안내·응답 시각·demo 표시, 표시 건수와 날짜별 합계, 해당 사건의 상세 | “학생이 받은 기록을 필터링하고 날짜별로 집계한 화면입니다. 지금 기록은 설명용 예시 자료이며 실제 보안 사건 조회가 아닙니다.” |
| 2. 내 PC 상태 | 보호 현황 → 제공 「내 PC 확인」 | 마지막 실측 시각, CPU %, 메모리 사용/전체, 앱 디스크 여유/전체와 단위. 네트워크 구성·방화벽·Windows 건수 또는 확인 불가 사유 | “이 값은 앱을 실행한 PC에서 제공 기능으로 읽었습니다. 학생은 수치 읽는 법을 더했고 측정 기능을 중복 구현하지 않았습니다. Windows 경고·오류 건수는 침해 판정이 아닙니다.” |
| 3. SDP 상태와 한계 | 제공 「도움정보 불러오기」 → 학생 상태·알림 영역의 SDP 연결 상태 | demo/DEMO_ONLY라면 「SDP 미연결 · 예제 모드로 실행 중」과 checkedAt. 진단이 없으면 확인 불가와 이유 | “PC를 읽을 수 있어도 SDP 서버에 연결됐다는 뜻은 아닙니다. 이것은 마지막 진단 응답 기준이며 실시간 감시가 아닙니다.” |

키보드 연습은 Tab으로 「기록 다시 조회」에 이동해 Enter로 실행한다. 응답이 빠르면 대기 문구가 잠깐만 보일 수 있다. 보지 못한 대기 표시를 직접 관찰했다고 기록하지 않는다. 대기를 보이려고 공격·권한 변경·임의 보안 설정 변경을 하지 않는다.

조회가 실패하면 실패한 항목·이유·다음 행동을 그대로 보여 준다. 이전 수치나 예시 값을 최신 정상 결과처럼 대신 쓰지 않는다. 실제 실패 재현을 하지 않았다면 과거 실패 캡처와 모의 검사 결과를 설명용 근거로 구분한다.

## 5. 실제 값·예시 값·시각·단위 구분

| 표시 | 출처와 의미 | 해석할 때의 한계 |
|---|---|---|
| 계정·기기·세션과 event-01 | Demo 예시 자료, 실제 조회 결과 아님 | 세션 active나 기록 응답 수신을 실제 SDP 연결 성공으로 보지 않는다. |
| CPU·메모리·디스크·네트워크·방화벽·Windows 건수 | 제공 내 PC 상태의 로컬 조회 응답 | PC 전체의 안전·인터넷 접속·ZTNA 허용을 보장하지 않는다. |
| 이 PC 마지막 실측 | PC 응답의 공통 measuredAt | 항목마다 별도 측정 시각이 제공된 것은 아니다. |
| 기록 응답 checkedAt | 학생 수동 재조회 응답 시각 | 사건 발생 시각(event.at)·PC 측정 시각과 다르다. |
| 진단 checkedAt | 마지막 도움정보 진단 시각 | 진단 이후 상태가 바뀔 수 있으며 자동 재요청하지 않는다. |

CPU 단위는 %, 메모리·디스크는 화면에서 GB로 표기하지만 계산 기준은 1024³바이트(GiB)다. 네트워크는 인터페이스·IPv4 구성 개수(개), Windows 기록은 최근 24시간의 건수(건)다. 방화벽은 Domain·Private·Public 설정의 켜짐 여부다. CPU는 약 200ms 표본의 짧은 구간 값이므로 작업 관리자와 갱신 시각·계산 방식이 달라질 수 있다. 숫자가 다르다는 이유만으로 예시 값이라고 판단하지 않는다.

## 7. 남은 한계와 확인 불가

- demo 계정·기기·세션·기록은 실제 연동 자료가 아니다. 현재 기기의 unknown 표시는 보안 기준 충족으로 바꾸지 않는다.
- 예제 모드에서는 SDP 미연결이다. 실제 학생 계정으로 SDP 서버 통신·세션 제어·보안 조치 효과는 검증하지 않았다. 진단이 없으면 미연결로 단정하지 않고 확인 불가로 표시한다.
- 실제 AI 모델의 사건 설명과 보안 조치 실행은 이번 마무리에서 검증하지 않았다. PC 조회 성공과 별개다.
- 기록은 최근 최대 40건의 받은 일부 이력이다. Windows 집계는 System·Application 최근 24시간, 최대 5,000건 범위이며 침해·공격 탐지가 아니다. 읽지 못한 값은 확인 불가와 이유로 남긴다.
- 권한 부족 PC 항목을 최종 디자인에서 실제로 재현하지 않았다. 모든 오류 경로가 실제 PC에서 검증됐다고 쓰지 않는다. 관리자 권한 상승·방화벽 변경·공격 모의시험은 안내하거나 수행하지 않았다.
- 최종 화면의 새 PC 실측·SDP 진단은 8장에 기록했다. 연습의 정확한 시작·종료 시각, 이번 기록 재조회 checkedAt, 최종 디자인에서의 실패·복구 재시험과 대기 문구 직접 관찰, 좁은 화면의 실제 배치, 전체 접근성 점검은 미수집 또는 미확인이다.
- 다른 사람의 안내만 보고 실행·새 PC·다른 사용자 계정에서의 독립 실행은 미확인이다. 동일 PC의 별도 폴더 재현은 AI 도움을 받았다.
- HTTP 로컬 서버 실행과 Node 환경이 필요하다. 서버 창을 종료하면 사이트에 연결할 수 없다. 임시 Node PATH는 새 창에서 다시 준비해야 한다.
- 과제 서버의 최종 제출·판정은 별도다. GitHub push와 화면 시연을 공식 통과 판정으로 표현하지 않는다.

## 9. 문서 저장 후 제출 커밋 확인

이 문서 한 개를 저장한 뒤 Git 백업용 폴더에서 변경 내용을 검토하고 커밋·push한다. 코드·환경·인증 설정이나 앞 단계 제출물은 이 문서 작업에서 변경하지 않는다. push가 거절되면 오류를 기록하고 원인을 확인하며 강제로 덮어쓰지 않는다.

마지막 40자리 번호는 **Git 백업 저장소**에서 확인한다. 재현 폴더는 별도 복제본이므로 제출 번호 조회 대상으로 혼동하지 않는다.

```powershell
git -C "$env:USERPROFILE\Desktop\naevis-dashboard-save" status --short
git -C "$env:USERPROFILE\Desktop\naevis-dashboard-save" rev-parse HEAD
```

변경 사항이 없으면 첫 명령은 출력이 없다. 다음 명령의 실제 40자리 번호를 제출문에 적고, GitHub의 naevis-dashboard 브랜치·커밋 화면과 대조한다. 문서를 추가했으므로 최종 제출 번호는 앱 기준 fe98aa8과 달라진다. 포장 명령은 실행하지 않는다.
