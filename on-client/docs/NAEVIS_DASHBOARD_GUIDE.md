# nævis 관제 대시보드 실행·확인 안내

작성일: 2026-11-03 (한국 시각)
대상: 시작 틀 0.2.21을 사용하며 학생 화면을 복원·개선한 프로젝트 폴더 실행본.
이 문서는 22단계 이후 화면 개선과 확인 기록이다. 이전 제출물·커밋의 실행 결과를 대체하지 않는다. 현재 변경본의 Git 커밋·원격 반영 여부는 미확인이다.

## 1. 실행 형태와 준비물

- Windows PC, PowerShell, Node.js가 필요하다. 이전 재현에서 사용자가 보고한 버전은 Node.js v24.19.0, PowerShell 5.1.26100.9711, Git 2.56.0.windows.2이다. 이번 화면 확인 시 버전을 다시 측정하지는 않았다.
- 포장 없이 기존 프로젝트 폴더에서 실행한다. 포장·설치 명령은 사용하지 않는다.
- 예제 계정·기록을 확인하는 데 SDP 개인 연결 설정·인증서·다른 사람의 자격 파일은 필요하지 않다. AI 연결·실제 사건 설명은 이 확인 절차의 필수 사항이 아니다.
- 예제 모드에서는 실제 SDP 서버에 연결하지 않는다. SDP 미연결은 이 시연에서 정상이며 실제 서버 연동 성공을 뜻하지 않는다. `-Demo`와 `-SdpHostConfig`를 함께 사용하지 않는다.
- 앱을 실행한 PC의 실측 기능은 예제 계정·기록과 별개다. 실제 수치가 반환된 항목만 실측으로 기록한다.

## 2. 작업 위치와 파일

현재 사용자 PC에서 확인한 실행 폴더:

```text
C:\Users\Administrator\AppData\Local\ALEPH\Workbench\projects\on-client
```

위 경로는 이번 PC의 작업 위치다. 다른 PC에서는 본인의 실제 프로젝트 폴더에서 실행한다. 바탕화면의 `naevis-step22` 등 이전 작업·제출 폴더는 이동하거나 덮어쓰지 않는다.

| 경로 | 역할 |
|---|---|
| `tools/start-alekov.ps1` | 제공 실행 도구 |
| `src/server.mjs` | 제공 로컬 앱 서버 |
| `public/app.js` | 제공 화면·조회 흐름 |
| `student/extension.mjs` | 학생 화면 함수. 이번 수정은 renderIdentity·renderEvents·renderStatus |
| `student/appearance.json` | 앱 이름 nævis, student-first 배치 |
| `docs/NAEVIS_DASHBOARD_GUIDE.md` | 이 실행·확인 문서 |

이번 작업에서는 제공 서버·public/app.js·판정·인증 설정을 수정하지 않았다. 제공 기능의 PC 실측 결과를 학생 구현 성취로 표시하지 않는다.

## 3. 시작·브라우저·종료·재실행

이미 서버가 실행 중이면 새 서버를 중복으로 켜지 않는다. 실행 모드를 바꿀 때는 해당 서버 PowerShell 창에서 Ctrl+C로 종료한 다음 시작한다.

PowerShell에서:

```powershell
Set-Location "$env:LOCALAPPDATA\ALEPH\Workbench\projects\on-client"
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
```

브라우저 주소: <http://127.0.0.1:5189/>

- 실행 도구가 앱 켜짐과 위 주소를 안내하고 브라우저에서 세 메뉴·학생 영역이 보이는지 확인한다. 서버 응답만으로 AI·SDP 연결 성공을 주장하지 않는다.
- 서버 창은 열어 둔다. 학생 파일을 적용한 뒤에는 브라우저에서 Ctrl+Shift+R로 다시 불러온다.
- 종료는 해당 서버 창에서 Ctrl+C. 재실행은 같은 폴더에서 위 명령을 다시 사용한다. 인증·설정 파일을 삭제하거나 다른 폴더에서 복사하지 않는다.
- 다른 PC에서 Node.js 설치나 의존성 설치가 필요하면 해당 프로젝트 README·package/lock의 실제 절차를 따른다. 이 기록은 새 PC의 설치 성공을 확인한 기록이 아니다.

## 4. 화면의 자료 구분

| 화면 | 자료·해석 |
|---|---|
| 내 PC 상태 | 제공 기능이 앱 실행 PC에서 조회한 값. 마지막 실측 시각과 함께 확인 |
| 사용자·기기·세션 네 카드 | 전달된 조회 결과. demo에서는 예시이며 실제 직원 계정·기기 상태가 아님 |
| 보안 기록·날짜별 집계 | 받은 최근 최대 40건만 집계. demo의 event-01은 예시 기록 |
| AI 연결 점검 | 별도 기능. 모델 목록 응답은 사건 설명 성공이 아님 |
| 보안 조치 상태 | 제안·접수·효과 관측을 구분하는 표시. 이번 확인에서 실제 조치 미실행 |

조회 실패·미조회·unknown을 정상 또는 0건으로 바꾸지 않는다. PC 방화벽이 켜졌다는 사실이나 Windows 경고·오류 건수로 감염·안전 여부를 판정하지 않는다. 네트워크 구성 개수는 인터넷 연결이나 ZTNA 접근 허용의 증거가 아니다.

## 6. 코드·모의 입력으로만 확인한 사항

별도 환경의 Node.js 구문 검사와 모의 DOM 입력으로 다음을 확인했다. 실제 브라우저의 모든 상태를 재현한 증거는 아니다.

- 네 카드, demo 표시, noncompliant·revoked·unknown의 문구, 오류 시 이전 사용자 제거.
- 한국 시각 날짜별 집계, 시각이 잘못된 기록의 집계 제외·목록 유지, 원본 배열 불변.
- 필터 변경에 따른 목록·집계 갱신과 상세 초기화. 기록 안의 HTML 모양 문자열을 글자로 표시.
- loading·빈 배열·error 구분과 진단 복사 버튼의 비활성 상태.
- 수정 대상 외 다섯 함수 원문 유지. 학생 수정 코드가 조회·조치 요청을 추가하지 않음.

## 7. 같은 결과를 다시 확인하는 순서

1. 위 명령으로 예제 모드 실행 후 주소를 연다. 앱 이름·세 메뉴·학생 네 카드를 확인한다.
2. 보안 기록에서 예시 표시, 목록 1건과 날짜별 합계 1건을 대조한다. 제공 예제 데이터가 달라지면 실제 받은 자료 기준으로 대조한다.
3. event-01 상세에서 근거·규칙·세 상태를 확인한다. 다시 불러오기로 상세가 닫히고 목록·집계가 다시 그려지는지 확인한다.
4. 보호 현황에서 내 PC 확인을 누른다. 실측 시각과 자료 구분을 확인하고 한 번 더 눌러 시각 갱신을 확인한다. 위의 과거 수치와 같아야 할 필요는 없다.
5. 서버 창에서 Ctrl+C로 종료한다. 같은 명령으로 재실행해 화면을 다시 연다. 재실행 후 확인은 이번 기록에서 별도 완료로 수집하지 않았다.

## 9. 미확인·지원 범위와 보존

- 실제 SDP 계정·기기·기록 연동과 실제 보안 조치는 이 시연에서 미사용·미검증이다. AI 실제 사건 설명도 이번 확인 범위에 포함하지 않는다.
- 여러 날짜의 실제 기록 추이·실제 XDR 경보는 미확인이다. 예제 화면 확인과 모의 입력 점검을 실제 탐지 성능으로 표현하지 않는다.
- 이번 재조회에서는 자동 10초 조회를 켜지 않았다. 자동 조회 성능·장시간 수집·다른 PC 실행은 확인하지 않았다.
- 현재 화면은 보호 현황의 네 카드와 보안 기록 메뉴의 집계·목록으로 나뉜다. 네 카드 아래 모든 기록이 합쳐진 단일 화면은 구현하지 않았다.
- 학생 코드 적용 전 백업은 프로젝트 밖 `%LOCALAPPDATA%\ALEPH\StudentBackups`에 만든 안내를 사용했다. 정확한 이번 백업 파일명은 사용자 실행 출력에서 확인한다.
- 기존 22단계 폴더·Git 기록·제출물을 보존한다. 복구할 때는 백업의 내용과 대상 파일을 먼저 대조하며 최신 작업을 무조건 덮어쓰지 않는다.
- 이 문서에는 개인 인증·설정 파일을 포함하지 않는다. 새 PC로 옮길 때 개인 자격은 별도 공식 절차를 따르고 문서·제출물·Git에 복사하지 않는다.
