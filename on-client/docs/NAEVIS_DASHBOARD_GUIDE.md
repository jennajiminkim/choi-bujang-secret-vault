# nævis 관제 대시보드 실행·확인 안내

작성일: 2026-11-03 (한국 시각)
대상: 시작 틀 0.2.21을 사용하며 학생 화면을 복원·개선한 프로젝트 폴더 실행본.
이 문서는 22단계 이후 화면 개선과 확인 기록이다. 이전 제출물·커밋의 실행 결과를 대체하지 않는다. 3일차까지의 GitHub 백업은 naevis-dashboard 브랜치의 123fbff로 사용자 커밋·push 출력에서 확인했다. 4일차 학생 코드의 PC 적용과 아래 화면 확인은 사용자 보고·캡처로 기록했다. 4일차 문서 적용·새 커밋·원격 반영은 아직 미확인이다.

## 1. 실행 형태와 준비물

- Windows PC, PowerShell, Node.js가 필요하다. 이전 재현에서 사용자가 보고한 버전은 Node.js v24.19.0, PowerShell 5.1.26100.9711, Git 2.56.0.windows.2이다. 이번 화면 확인 시 버전을 다시 측정하지는 않았다.
- 포장 없이 기존 프로젝트 폴더에서 실행한다. 포장·설치 명령은 사용하지 않는다.
- 예제 계정·기록을 확인하는 데 SDP 개인 연결 설정·인증서·다른 사람의 자격 파일은 필요하지 않다. AI 연결·실제 사건 설명은 이 확인 절차의 필수 사항이 아니다.
- 예제 모드에서는 실제 SDP 서버에 연결하지 않는다. SDP 미연결은 이 시연에서 정상이며 실제 서버 연동 성공을 뜻하지 않는다. `-Demo`와 `-SdpHostConfig`를 함께 사용하지 않는다.
- 앱을 실행한 PC의 실측 기능은 예제 계정·기록과 별개다. 실제 수치가 반환된 항목만 실측으로 기록한다.

## 2. 작업 위치와 파일

현재 사용자 PC에서 확인한 실행 폴더:

```text
C:\Users\Administrator\AppData\Local\ALEPH\Workbench\projects\on-client
```

위 경로는 이번 PC의 작업 위치다. 다른 PC에서는 본인의 실제 프로젝트 폴더에서 실행한다. 바탕화면의 `naevis-step22` 등 이전 작업·제출 폴더는 이동하거나 덮어쓰지 않는다.

| 경로 | 역할 |
|---|---|
| `tools/start-alekov.ps1` | 제공 실행 도구 |
| `src/server.mjs` | 제공 로컬 앱 서버 |
| `public/app.js` | 제공 화면·조회 흐름 |
| `student/extension.mjs` | 학생 화면 함수. 이번 수정은 renderIdentity·renderEvents·renderStatus |

| `docs/NAEVIS_DASHBOARD_GUIDE.md` | 이 실행·확인 문서 |

이번 작업에서는 제공 서버·public/app.js·판정·인증 설정을 수정하지 않았다. 제공 기능의 PC 실측 결과를 학생 구현 성취로 표시하지 않는다.

## 3. 시작·브라우저·종료·재실행

이미 서버가 실행 중이면 새 서버를 중복으로 켜지 않는다. 실행 모드를 바꿀 때는 해당 서버 PowerShell 창에서 Ctrl+C로 종료한 다음 시작한다.

PowerShell에서:

```powershell
Set-Location "$env:LOCALAPPDATA\ALEPH\Workbench\projects\on-client"
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
```

브라우저 주소: <http://127.0.0.1:5189/>

- 실행 도구가 앱 켜짐과 위 주소를 안내하고 브라우저에서 세 메뉴·학생 영역이 보이는지 확인한다. 서버 응답만으로 AI·SDP 연결 성공을 주장하지 않는다.
- 서버 창은 열어 둔다. 학생 파일을 적용한 뒤에는 브라우저에서 Ctrl+Shift+R로 다시 불러온다.
- 종료는 해당 서버 창에서 Ctrl+C. 재실행은 같은 폴더에서 위 명령을 다시 사용한다. 인증·설정 파일을 삭제하거나 다른 폴더에서 복사하지 않는다.
- 다른 PC에서 Node.js 설치나 의존성 설치가 필요하면 해당 프로젝트 README·package/lock의 실제 절차를 따른다. 이 기록은 새 PC의 설치 성공을 확인한 기록이 아니다.

## 6. 코드·모의 입력으로만 확인한 사항

별도 환경의 Node.js 구문 검사와 모의 DOM 입력으로 다음을 확인했다. 실제 브라우저의 모든 상태를 재현한 증거는 아니다.

- 네 카드, demo 표시, noncompliant·revoked·unknown의 문구, 오류 시 이전 사용자 제거.
- 한국 시각 날짜별 집계, 시각이 잘못된 기록의 집계 제외·목록 유지, 원본 배열 불변.
- 필터 변경에 따른 목록·집계 갱신과 상세 초기화. 기록 안의 HTML 모양 문자열을 글자로 표시.
- loading·빈 배열·error 구분과 진단 복사 버튼의 비활성 상태.
- 수정 대상 외 다섯 함수 원문 유지. 학생 수정 코드가 조회·조치 요청을 추가하지 않음.

## 7. 같은 결과를 다시 확인하는 순서

1. 위 명령으로 예제 모드 실행 후 주소를 연다. 앱 이름·세 메뉴·학생 네 카드를 확인한다.
2. 보안 기록에서 예시 표시, 목록 1건과 날짜별 합계 1건을 대조한다. 제공 예제 데이터가 달라지면 실제 받은 자료 기준으로 대조한다.
3. event-01 상세에서 근거·규칙·세 상태를 확인한다. 다시 불러오기로 상세가 닫히고 목록·집계가 다시 그려지는지 확인한다.
4. 보호 현황에서 내 PC 확인을 누른다. 실측 시각과 자료 구분을 확인하고 한 번 더 눌러 시각 갱신을 확인한다. 위의 과거 수치와 같아야 할 필요는 없다.
5. 서버 창에서 Ctrl+C로 종료한다. 같은 명령으로 재실행해 화면을 다시 연다. 재실행 후 확인은 이번 기록에서 별도 완료로 수집하지 않았다.

## 9. 미확인·지원 범위와 보존

- 실제 SDP 계정·기기·기록 연동과 실제 보안 조치는 이 시연에서 미사용·미검증이다. AI 실제 사건 설명도 이번 확인 범위에 포함하지 않는다.
- 여러 날짜의 실제 기록 추이·실제 XDR 경보는 미확인이다. 예제 화면 확인과 모의 입력 점검을 실제 탐지 성능으로 표현하지 않는다.
- 이번 재조회에서는 자동 10초 조회를 켜지 않았다. 자동 조회 성능·장시간 수집·다른 PC 실행은 확인하지 않았다.
- 현재 화면은 보호 현황의 네 카드와 보안 기록 메뉴의 집계·목록으로 나뉜다. 네 카드 아래 모든 기록이 합쳐진 단일 화면은 구현하지 않았다.
- 학생 코드 적용 전 백업은 프로젝트 밖 `%LOCALAPPDATA%\ALEPH\StudentBackups`에 만든 안내를 사용했다. 정확한 이번 백업 파일명은 사용자 실행 출력에서 확인한다.
- 기존 22단계 폴더·Git 기록·제출물을 보존한다. 복구할 때는 백업의 내용과 대상 파일을 먼저 대조하며 최신 작업을 무조건 덮어쓰지 않는다.
- 이 문서에는 개인 인증·설정 파일을 포함하지 않는다. 새 PC로 옮길 때 개인 자격은 별도 공식 절차를 따르고 문서·제출물·Git에 복사하지 않는다.


## 10. 2일차: 제공 PC 조회 재사용과 학생 설명

### 기준과 변경 범위

1일차 GitHub 백업 확인 커밋은 `ff0e0b2f68600027ae568c6cf58fa2b041ef3dbc`, 브랜치는 `naevis-dashboard`다. 아래 2일차 추가분은 그 이후 작업이다. 사용자 캡처·보고로 PC 적용·설명 패널·키보드 조작과 비교 관찰을 확인했다. 이후 사용자가 보고한 커밋 생성·push 출력에서 2일차 커밋 d93af07과 origin/naevis-dashboard 반영을 확인했다. 40자리 해시는 이번 기록에서 수집하지 않았다. 기록된 버전·시각을 다른 커밋 전체의 성공으로 합치지 않는다.

- 선택한 추가 기능: 학생 상태 영역의 접이식 「PC 수치 읽는 법」. 실측값 자동 분석·추이 수집 기능이 아니라 측정 범위·단위·시각을 읽는 설명이다.
- 학생 변경: `student/extension.mjs`의 renderStatus와 이 문서만 수정한다. 네 카드·기록 추이·앞 단계 함수는 유지한다.
- 제공 기능 유지: `src/pc-status.mjs`의 CPU·메모리·디스크 수집, `public/pc-status-view.mjs`의 표시·내 PC 확인, `public/app.js`의 연결은 수정하지 않는다.
- 새 수집·추가 API 요청·관리자 권한·유료 AI·포장 명령은 추가하거나 실행하지 않는다.

| CPU 사용률 | src/pc-status.mjs: cpuUsage, system.cpus() 두 표본 사이 약 200ms | usagePercent, %. 실제 지연은 달라질 수 있음 | 응답 공통 measuredAt. 개별 표본 시각은 미제공 |
| 메모리 사용량 | system.totalmem() - system.freemem() | usedBytes / totalBytes. 화면은 GB 표기지만 1024³바이트로 나누므로 GiB 계산 기준 | 응답 공통 measuredAt. 메모리 개별 시각은 미제공 |
| 디스크 여유 공간 | statfs(directory)의 bavail×bsize와 blocks×bsize | freeBytes / totalBytes. 앱 폴더가 있는 디스크. 위와 같은 용량 표시 기준 | 응답 공통 measuredAt. 디스크 개별 시각은 미제공 |

응답의 source는 local-pc, schema는 aleph.on.pc-status.v1이다. measuredAt은 조회들을 마친 뒤 응답을 만드는 시각이다. 학생 함수 입력에는 이 PC 응답이 없으므로 현재 실측값·항목별 시각을 만들어 표시하지 않는다. 제공 화면의 공통 실측 시각을 각 항목의 개별 측정 시각으로 오인하지 않는다. 항목별 시각을 수집·표시하는 기능은 이번 범위에서 미구현이다.

실패한 항목은 제공 화면의 확인 불가·실패 이유를 유지한다. 학생 설명은 권한 부족·시간 초과·미지원 등의 뜻을 설명할 뿐 실제로 어떤 오류가 발생했다고 새로 판정하지 않는다. 예시 수치를 채우거나 관리자 권한으로 재실행하지 않는다.

### 2일차 직접 확인 순서

앱 실행은 3장의 기존 명령을 재사용한다. 기존 서버가 켜져 있으면 중복 실행하지 않는다. 포장하지 않는다.

1. 학생 파일을 적용한 뒤 Ctrl+Shift+R. 보호 현황→학생 상태·알림 표시에서 「PC 수치 읽는 법」을 Tab으로 선택하고 Enter 또는 Space로 열고 닫는다. 표의 CPU·메모리·디스크 설명과 실측이 아니라는 안내를 확인한다.
2. 제공 「내 PC 상태」에서 「내 PC 확인」을 한 번 누른다. CPU %, 메모리 사용량/전체, 디스크 여유/전체와 공통 실측 시각을 기록한다. 읽지 못한 항목은 확인 불가와 이유를 그대로 적는다.
3. 가까운 시각에 Ctrl+Shift+Esc로 작업 관리자→성능에서 CPU·메모리를 확인하고, 파일 탐색기→내 PC에서 앱이 있는 같은 드라이브의 여유 공간을 비교한다. 일반 권한으로만 진행하고 권한 상승을 요구하면 취소한다. 집계 범위·단위·측정 시각의 차이를 먼저 확인한다.
4. 아래 표는 2일차 사용자 캡처·보고의 관찰값이다. 비교 화면의 정확한 시각이 없는 항목은 미수집으로 남긴다. 1일차 수치를 현재 측정값으로 재사용하지 않는다.

- 사용자 캡처에서 「PC 수치 읽는 법」 설명이 표시됨을 확인했다. 사용자는 Tab·Enter로 닫고 열기를 반복했다고 보고했다. 키보드 확인의 정확한 시각은 미수집이다.

- 이 수치는 사용자의 PC에서 제공 기능으로 읽은 당시 값이며 예시 수치가 아니다. 별도로 demo 계정·기기·세션·기록은 설명용 자료로 유지된다.
- 학생 구현은 설명 패널과 문서다. 실제 수집·PC 상태 카드는 제공 기능이며 중복 구현하지 않았다.
- CPU·디스크 차이의 정확한 원인, 실제 읽기 권한 거부·시간 초과·미지원 화면, 여러 PC 재현, 항목별 측정 시각은 미확인이다. 수집된 자료로 모든 항목의 정확성이 검증되었다고 주장하지 않는다.
- 관리자 권한 실행·설정 변경·공격 모의·실제 보안 조치·포장 명령은 이번 확인 절차에서 수행하도록 요청하지 않았다.


## 11. 3일차: 읽기 전용 PC 조회와 SDP 진단 분리

### 유지·변경 경계

| 구분 | 파일·함수 | 내용 |
|---|---|---|
| 제공 기능 유지 | src/pc-status.mjs: createPcStatusReader, normalizeWindowsStatus | 로컬 네트워크 구성, 방화벽 프로필, Windows 기록 읽기. 변경하지 않음 |
| 제공 기능 유지 | public/pc-status-view.mjs, public/app.js | 내 PC 확인·값·단위·시각·확인 불가 표시와 수동 도움정보 조회. 변경하지 않음 |

renderStatus 입력은 devices, sessions, notifications, diagnostics, mode이다. PC 실측 응답은 입력에 없다. 새 수집 API·관리자 권한·방화벽 변경·공격 모의·AI 요청·포장 명령은 추가하지 않는다. 제공 기능의 조회를 학생 기능으로 중복 구현하지 않는다.

### 조회 범위와 제한

| 항목 | 실제 제공 입력·단위 | 해석 |
|---|---|---|
| 네트워크 | os.networkInterfaces()에서 내부 인터페이스를 제외한 인터페이스·IPv4 구성 개수(개) | 유선·무선 또는 인터넷 통신 여부 판정이 아님 |
| 방화벽 | Get-NetFirewallProfile의 Domain·Private·Public enabled | 읽기 전용. 켜짐이 전체 안전 판정은 아님 |
| Windows 기록 | Get-WinEvent로 최근 24시간 System·Application Level 2·3을 조회, 최신 최대 5,000건의 경고·오류(건) | 침해·공격 탐지 결과가 아님. 상한 초과 시 일부 집계. Security 로그는 대상 아님 |
| PC 시각 | 제공 응답의 공통 measuredAt | 각 항목의 개별 측정 시각은 미제공 |
| SDP 시각 | diagnostics.data.checkedAt | 진단 응답 시각. PC 측정 시각·실제 통신 성공 시각이 아님 |

제공 조회는 일반 권한으로 실행한다. permission_denied, timeout, unsupported 등은 제공 화면의 확인 불가·이유를 그대로 확인한다. 권한을 바꾸거나 예시 수치로 채우지 않는다. 실제 권한 거부·시간 초과 화면은 이번 단계에서 미확인이다.

### SDP 표시 계약

GET /api/diagnostics의 성공 응답에서 engine.mode·engine.code·checkedAt을 사용한다. 제공 public/app.js는 이를 diagnostics.status/mode/data로 학생 함수에 전달한다. 진단은 실제 SDP 통신 탐침이 아니라 구성 상태에 따른 응답이다. 진단 자료 모드와 engine.mode가 일치할 때만 아래 조합을 표시한다.

| engine.mode / engine.code | 학생 표시 |
|---|---|
| demo / DEMO_ONLY | SDP 미연결 · 예제 모드로 실행 중. 계정·기기·세션·기록은 예시 자료 |
| disconnected / ENGINE_NOT_CONNECTED | SDP 미연결 · 연결 어댑터 미연결 상태 |
| connected / ADAPTER_CONFIGURED | SDP 연결 설정 있음 · 실제 통신 성공 여부는 이 진단으로 확인 불가 |
| 미조회·불러오는 중·조회 실패·모드 불일치·필드 누락·알 수 없는 조합 | SDP 연결 상태 확인 불가와 이유 |

checkedAt은 유효한 시간대 포함 날짜 문자열일 때 원문 시각을 표시한다. 없거나 잘못되면 시각 확인 불가다. 이전 진단이 화면에 남아도 현재 실시간 연결을 보장하지 않는다. 최신 진단은 제공 「도움정보 불러오기」를 수동으로 누른다. PC 실측 성공과 AI verified만으로 SDP 연결 성공을 판정하지 않는다.

### 적용 후 사용자가 확인할 순서

1. 학생 파일을 백업하고 수정본을 적용한 뒤 기존 브라우저에서 Ctrl+Shift+R. 「SDP 연결 상태」가 표시되는지 확인한다. 진단을 아직 조회하지 않았다면 확인 불가가 맞으며, 실패를 미연결로 단정하지 않는다.
2. 제공 「도움정보 불러오기」를 한 번 누른다. 예제 실행에서 demo / DEMO_ONLY라면 「SDP 미연결 · 예제 모드로 실행 중」과 진단 응답 시각을 확인한다. JSON을 PowerShell에 붙여넣지 않는다.
3. 「네트워크·방화벽·Windows 기록 읽는 법」을 Tab·Enter 또는 Space로 열고 닫는다. 읽기 전용·침해 판정 아님·확인 불가 안내를 확인한다.
4. 제공 「내 PC 확인」을 한 번 누른다. 네트워크 구성 개수, 세 방화벽 프로필, 경고·오류 건수 또는 확인 불가 이유와 PC 공통 실측 시각을 기록한다. 예시 화면의 값을 복사하지 않는다.

실행·종료·재실행은 3장의 -Demo 명령을 그대로 사용한다. 서버가 켜져 있으면 중복 실행하지 않는다. 포장하지 않는다.

### 입력·조회·시간 계약

- createStudentView는 제공 공통 화면이 넘기는 api를 받는다. api.get('/api/events')는 {ok, data 또는 error, meta, 선택 coverage} 형태로 반환된다. 허용 주소는 공식 제공 코드에서 확인했다. 학생 API로 SDP 도움정보 주소를 우회 호출하지 않는다.
- 최초 renderEvents 입력은 제공 화면이 검사한 {status, mode, data, error}다. checkedAt이 전달되지 않아 최초 학생 표시의 응답 시각은 확인 불가다. 임의의 현재 시각을 측정 시각으로 만들지 않는다.
- 학생 재조회 성공에서는 최근 최대 40건 배열, 고유 ID·기록 종류·시각·근거·규칙·상태·지원 조치의 기존 형식을 검사한다. 선택 coverage가 있으면 scope·limit·returned·total·truncated와 요청 전후의 observedAtMs 범위를 검사한다. 맞지 않으면 CONTRACT_MISMATCH다.
- 재조회 시각은 서버가 전달한 meta.checkedAt이 유효한 시간대 포함 문자열일 때만 표시한다. 이는 응답 시각이며 사건 발생 시각(at)·PC 측정 시각(measuredAt)·실제 SDP 연결 성공 시각이 아니다. 없거나 잘못되면 확인 불가다.
- 버튼을 누르면 이전 학생 목록·상세·집계를 현재 결과에서 비우고 「기록 조회 중…」을 표시한다. 완료하면 새 자료로 그리며 필터·상세는 초기화한다. 진행 중 중복 요청은 막고 자동 재시도하지 않는다.
- 제공 화면에서 새 입력이 렌더되면 늦게 도착한 이전 학생 요청으로 덮어쓰지 않는다. 버튼 DOM을 유지해 재조회 완료 후 초점이 사라지지 않도록 한다. aria-disabled·실행 가드·aria-busy·상태 텍스트를 사용한다. 실제 스크린리더 음성 출력은 미확인이다.
- 실패 시 실패한 항목·코드·이유와 다음 행동을 표시한다. 이전 자료·예시 값·0건을 성공 결과로 대신 표시하지 않는다. 서버 자체가 demo 응답을 주는 경우는 예시 자료 표시와 함께 유지한다.

| 학생 API 사용 불가 | 제공 공통 화면의 「다시 불러오기」 사용. 허용되지 않은 경로나 직접 fetch로 우회하지 않음 |
| 예시 자료(demo) | 현재 예제 실행에 맞는 출처 표시. 실제 학생 계정·SDP 보안 기록 조회 성공으로 해석하지 않음 |
| PC 조회 또는 SDP 도움정보도 갱신하고 싶은 경우 | 각각 제공 「내 PC 확인」·「도움정보 불러오기」 사용. 학생 기록 버튼은 이 두 상태를 갱신하지 않음 |

현재 4일차 학생 코드 적용과 위 사용자 화면 확인까지만 기록했다. 이 문서의 PC 적용·4일차 새 커밋·GitHub 백업은 아직 미확인이다. 백업 시 학생 코드와 이 문서 두 파일만 검토하며 기존 제출 브랜치 main은 변경하지 않는다.
