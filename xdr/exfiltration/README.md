# 보너스 xdr-06 · 자료 빼돌리기 탐지

`read-alerts.mjs`는 시각·출발 주소·계정·규칙 수준·설명 다섯 항목만 JSONL로 출력합니다. 목적지·원본·full_log·토큰은 출력하지 않으며 다섯 항목 안의 비밀값 표기도 가립니다. 판단 함수는 읽기 모듈을 불러오지 않습니다.

`patterns.json`에는 T1041(기존 C2 통로 반출)·T1048(다른 프로토콜 반출)을 근거로 낯선 목적지 대용량 전송, 시간 밖 압축 파일 반출, 불충분한 외부 전송 신호의 이름·조건·근거 한 줄·공식 출처를 적었습니다. 태그와 전송 경보만으로 실제 C2 프로토콜이나 파일 내용을 확인했다고 주장하지 않습니다.

`decide.mjs` 상단의 PATTERNS는 JSON과 같으며 내보내는 함수는 decide(alert) 하나입니다. import·외부 패키지·파일·네트워크·호출 간 상태가 없습니다. 입력 설명 길이와 정수 형식을 제한하고 결과 이유에 원본·계정·주소를 복사하지 않습니다.

관련 태그와 수준 10 이상, 목적지와 50,000,000바이트 이상의 실제 전송량을 함께 확인합니다. 이때 낯선 목적지·평소와 다른 포트·짧은 시간 전체 외부 복사·같은 목적지 5회 이상 중 근거가 있으면 0.95 block 후보입니다. 대용량 압축 전송에 낯선 목적지 또는 업무 시간 밖이라는 근거가 겹치면 0.96 block 후보입니다. 소량·평소 목적지·일회 증가·압축 생성만·실패·전송 미확인은 0.6 alert, 일반 이벤트는 0.1 record입니다.

0.85 이상 block, 0.5 이상 alert, 나머지는 record입니다. 50MB·반복 5회·수준·확신도는 학습용 정책이며 MITRE가 정한 보편적인 기준이나 통계적 확률이 아닙니다. timestamp만으로 근무 시각을 지어내지 않고 수집기의 시간·목적지·포트 비교 요약을 사용합니다. 실제 기준 목록과 전송 통계 수집은 별도 운영 수집기의 책임입니다. 이 도구는 이미 반출된 데이터를 회수하거나 USB 저장을 차단하는 프로그램이 아닙니다.

## 실행과 로컬 결과

```bash
node xdr/exfiltration/read-alerts.mjs
npm run xdr:run -- exfiltration
node xdr/exfiltration/respond.mjs --replay
node --test test/exfiltration.test.mjs
```

경보 30건/읽기 30줄, block 10·alert 10·record 10입니다. 정상 연습 이벤트(수준 3 이하) 10건의 block은 0건입니다. 재생에서는 후보 10건만 목적지 거부 규칙을 적용하고 애매한 10건은 알림만 기록했습니다. 신규 시험 5개와 기존 XDR 시험 30개, 기존 판정기 연습 4항목이 통과했습니다. 독립 실행·패턴 일치·용량/반복 경계·부정확한 정수·실패·소량·정상 목적지·만료·중복·과거 경보를 확인했습니다.

## 목적지 추가 거부 어댑터

respond()는 결정을 다시 계산하고 유효한 경보 번호·목적지 IP·신선한 시각이 있는 block 후보만 TTL 15분의 추가 거부 규칙으로 저장합니다. ruleId는 xdr.exfiltration.destination_ip이며 destinationIp·expiresAt·alertIds를 포함합니다. srcip를 목적지로 대체하지 않습니다. 여러 목적지를 요약한 경보도 dstip에 실제로 명시된 한 곳만 대상으로 하며 나머지 주소를 추측하지 않습니다. live와 replay는 분리하고 같은 root는 한 writer가 직렬 처리합니다.

withExfiltration(baseDecide, options)는 기존 판정 결과를 먼저 적용하고 호스트의 destinationIpForRequest(request)로 검증된 실제 전송 목적지를 받아 추가 거부만 수행합니다. createZtnaDecider(options)는 기존 판정기와 연결합니다. 기존 deny와 정상 정책 결과를 보존하며 응답은 기존 다섯 항목으로 유지합니다. denyResponse는 운영 엔진에 등록된 추가 규칙·거부 응답을 공급해야 합니다.

현재 판정 요청 18항목에는 외부 전송 목적지가 없으므로 새 요청 필드를 추가하거나 브라우저가 보낸 URL·헤더를 그대로 믿지 않습니다. 실제 egress 호스트의 검증된 목적지 전달과 엔진 추가 규칙 등록이 연결돼야 운영 차단이 됩니다. DNS를 사용하면 검증한 IP와 실제 연결 IP를 묶고 재해석 우회도 막아야 합니다. Vercel 임시 파일을 운영 공용 거부 저장소라고 간주하지 않습니다. 지금은 로컬 재생·시험 정책의 목적지 거부/정상 통과까지 확인했으며 실제 운영 반출 차단은 미실행입니다. 기존 RULE_IDS·자료 API·DB·다른 XDR 규칙은 수정하지 않았습니다.

알림은 xdr/alerts.log에 메타데이터만 JSON 한 줄씩 추가합니다. 원본·계정·파일명·목적지·전송 본문·토큰은 알림에 쓰지 않습니다. 런타임 거부 규칙과 재생 규칙·임시 파일·공유 로그는 Git에서 제외하고 result.json을 저장합니다.
