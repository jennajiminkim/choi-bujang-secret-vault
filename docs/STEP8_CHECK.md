# 8단계 자원 구역과 직접 확인

## 현재 권한 구조

| 구역 | 판정기의 역할 | 최종 자료 API |
|---|---|---|
| `/api/notes` | 검증된 사용자·등록 기기·쿼리 없음일 때 GET/POST 진입 허용 | 본인 목록만 반환, 새 메모 소유자는 로그인 ID로 고정 |
| `/api/notes/:id` | UUID 단건 GET/PUT/DELETE 진입 허용 | 인증된 사용자와 저장된 소유자를 같은 SQL 조건에서 재대조; 타인 404 |
| `/notes/:id` | subjectId 또는 `subjectId--이름`인 논리 ID만 GET/PUT 허용 | 우리 정책의 논리 구역 규약; 실제 엔진 연결은 미확인 |
| `/notes` | 전체 목록 거부 | 실제 화면의 소유자 필터 API 목록은 위 별도 경로로 유지 |
| 공지 읽기 | 검증된 주체 허용 | 로그인 다시 검증 |
| 공지 수정 | 확인된 강사 계약이 없으므로 기본 거부 | 저장된 vault_instructors와 UPDATE RPC 권한 재확인 |

**API 진입 allow는 그 행의 소유권을 확인했다는 뜻이 아닙니다.** 실제 API에서 B의 A 메모는 404로 막습니다. 판정기만 평가하는 논리 경로에서는 명시적인 주체 ID 구역으로 B의 A 자료를 거부합니다. 이 규약은 우리가 정의한 정책이며 공개 엔진이나 심판의 ID 형식으로 확인된 것이 아닙니다. 확인되지 않은 일반 ID는 주인을 추측하지 않고 거부합니다. 최초로 방문한 사용자를 주인으로 기억하지 않습니다.

정확한 service·method·path·route를 대조하며 기능 경로·계층 이탈·인코딩 우회를 거부합니다. 엔진 입력의 쿼리는 길이 0이어야 합니다. 실제 API는 기존대로 id 쿼리만 받으며 role/owner/action 선택자를 거부합니다. UUID 슬롯에 export 같은 기능 경로를 두지 않습니다.

기본 판정기는 DB·서버 키·vault_subject_links를 조회하지 않습니다. 선택적 createResourceAuthorizer는 운영자가 공식 연결을 제공할 때만 주입할 수 있고, 이 함수의 허용 실패를 기본 진입 허용으로 바꾸지 않습니다. 사용자에게 운영 식별값을 추측해 넣거나 비밀값을 공유하도록 요구하지 않습니다.

## 사용자가 보고한 DB 상태

가상 공지 한 건을 추가했고 vault_instructors는 비어 있습니다. 강사 계정이 없으면 그대로 둡니다. 이 표가 비어 있는 상태에서 학생의 공지 수정은 403이 정상입니다. vault_subject_links는 현재 기본 판정기와 API에 필요하지 않으므로 추가로 채울 필요가 없습니다. 이미 있는 행이나 다른 테이블·자료·Auth 계정은 지우지 않습니다.

공지 스키마와 RPC가 아직 없는 새 환경에서만 supabase/step8_resources.sql을 검토해 SQL Editor에서 실행합니다. 이미 적용된 학습 환경의 메모 소유자·기존 권한·계정을 수정하지 않습니다. Table Editor에서 관리자 권한으로 행을 바꾼 것은 API 권한 시험이 아닙니다.

## 브라우저에서 본인 읽기와 다른 구역 거부 확인

1. 기존 자료실에서 A로 로그인해 가상 메모를 만들고 개별 읽기·수정·새로고침을 확인합니다. A 메모 UUID 하나를 로컬에서만 확인합니다.
2. 다른 브라우저 창에서 B로 로그인합니다. B의 자기 메모도 읽히고 A 메모는 목록에 없어야 합니다.
3. B 창 개발자 도구 Network의 메모 요청에서 Copy as fetch를 사용하고 B 창 Console에서 주소의 UUID만 A 메모 UUID로 바꾸어 GET/PUT/DELETE를 실행합니다. 각 응답은 자료 없이 404여야 합니다. 토큰이 포함된 요청을 채팅·스크린샷·공유 파일에 넣지 않습니다.
4. 같은 B의 인증된 요청을 가상 공지 UUID로 PUT하면 403 instructor_required여야 합니다. 본문 role을 추가해도 수정할 수 없어야 합니다. 공지 GET은 로그인 상태에서 허용됩니다.
5. 승인된 강사 계정이 없으면 강사 PUT 200 시험은 미실행으로 남깁니다. 이름을 강사처럼 바꾸어 권한을 만들지 않습니다.
6. /api/notes/export와 ?action=export는 자료 없이 거부되어야 합니다. 응답의 X-Resource-Id로 notes와 notices가 구별됩니다.

주소창으로 API를 여는 것은 Bearer 인증을 보내지 않아 401이 될 수 있습니다. 이 결과는 로그인한 B의 A 메모 거부를 대신하지 않습니다.

## 로컬 판정과 제출

```bash
npm run test:stage8
npm run decider:test
npm run fixture:7
```

31개 시험이 통과했습니다. 연결표가 없는 가상 DB와 실제 API 처리기로 본인 개별 읽기 200, B의 A GET/PUT/DELETE 404, 일반 학생 공지 PUT 403을 시험했습니다. 실제 학습 DB 계정으로 시험한 결과는 아닙니다. 논리 자원은 다른 사용자가 먼저 요청하거나 사용자의 접두어가 비슷해도 거부되고 본인만 허용됩니다. 기기 등록과 복합 이상 step_up도 유지합니다.

fixture:7의 자료 경로를 명시적인 learner_fixture--demo 소유자 구역으로 변경했습니다. 로컬 시험을 통과하도록 실제 심판 형식을 확인했다는 뜻은 아닙니다. 기본 판정기는 임의의 UUID 소유자를 요청 18항목만으로 구별할 수 없으며 최종 API에서 권한을 다시 확인합니다.

커밋 뒤 npm run bundle로 JSON을 갱신하고 /aleph.json의 step 8과 최신 커밋을 확인합니다. **심판의 정상 요청 원문과 자원 구역 규약은 미확인이므로 S08_OWN_BROKEN 해결·재채점 통과를 보장하지 않습니다.** 실제 심판이 다른 논리 ID를 사용한다면 운영 측의 확인된 계약/연결이 필요합니다. 실제 새 로그인 확인·운영 계정 API 시험·강사 계약은 실행하지 않았으면 미실행으로 기록합니다.
