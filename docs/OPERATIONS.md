# 탈환 작전실 사용과 기록 계약

## 설치와 실제 확인

GitHub main의 최신 검사 커밋을 확인하고 npm install 및 README의 시험 명령을 실행합니다. 수업의 ALEPH SDP 엔진은 제공 엔진입니다. 이 저장소는 학생 판정·탐지 모듈을 내보내며 기기 확인/사건 전달/실제 회수에 관한 엔진 내부 설치 명령을 제공하지 않습니다. 브라우저가 보내는 identity·role·deviceRegistered를 판정기의 검증 정보로 승격하지 않습니다.

기존 Supabase SQL Editor에서 step12_operations.sql과 step12_operations_mutations.sql을 순서대로 적용하고 승인된 앱에서 탈환 작전실 보기 버튼을 누릅니다. 작전실 보기에서는 메모 영역을 숨기며 내 메모 보기로 기존 화면에 돌아갈 수 있습니다. 추가 SQL은 메모나 기존 감사 표를 수정하지 않습니다. 아직 표가 없으면 실제 API의 조회 실패를 저장소 미설정으로 표시합니다. 0건 성공으로 대신 표시하지 않습니다.

1. 익명 자료 요청 거부와 확인값 없는 자료 요청 거부를 실행합니다. HTTP 401/403과 요청 ID·서버 확인 시각이 표에 저장되는지 확인합니다.
2. 본인 목록/본인 메모 읽기를 실행합니다. 실제 본인 메모 ID를 지정하면 HTTP 200이 저장됩니다. 목록 허용은 API의 소유자 필터 결과이며 판정기에서 전체 목록을 허용하는 규칙으로 변경하지 않았습니다.
3. B 승인 앱에서 A의 실제 존재하는 메모 ID로 타인 메모 점검을 실행합니다. HTTP 404를 확인합니다. 존재하지 않는 ID로 대신하지 않습니다.
4. B의 기존 사전 백업 ID로 백업 재검증을 실행합니다. HTTP 200과 verified/currentMatches의 boolean만 기록합니다. 이 버튼은 복원을 실행하지 않습니다.
5. 서버 기록 새로고침 후 가린 기록 JSON을 내려받습니다. checks.records 길이와 totals.recorded, matched/mismatched/unavailable가 화면과 맞는지 대조합니다. scope는 항상 본인 최근 50개입니다. 다른 사용자의 기록이나 메모 본문은 반환하지 않습니다.

## 요청·출처·저장 범위

GET /api/operations는 기존 로그인과 현재 앱 승인 검사를 거쳐 본인 기록과 요약만 반환합니다. POST는 {caseId} 또는 {caseId,noteId/backupId}만 받습니다. 이 POST 경로는 읽기 점검 7개를 지원하며 임의 URL·원문 토큰·본문·역할·기대값·실제 상태·통과 표시를 받지 않습니다. 보호 API의 서버 생성 X-Request-Id를 읽고, 없는 경우 null로 남깁니다. 별도의 check_id는 점검 API가 만든 UUID입니다. checked_at은 서버가 응답 확인 뒤 만든 UTC ISO 시각입니다.

server_http는 서버가 실제로 보낸 HTTP 요청의 상태입니다. server_api는 인증·기기 확인 뒤 기존 메모 PUT/공지 PUT/복원 POST API가 선택한 실제 응답 상태를 응답 전 기록한 것입니다. 브라우저 수신 여부까지 입증하지는 않습니다. 메모 수정과 복원 본문은 해당 원래 API에서만 처리하고 기록에는 복사하지 않습니다. 기록 실패면 X-Operations-Recorded: false로 알리며 이미 완료된 수정을 다시 실행시키지 않습니다. API 기대 일치는 상태·application/json 형식·서버 요청 UUID를 모두 확인합니다. HTML 200·읽을 수 없는 사전 백업 응답을 정상으로 처리하지 않습니다. 공개 화면 점검은 HTML 응답이며 API 결과와 구분합니다. user_report는 이전 사용자 보고이며 자동 실측으로 취급하지 않습니다. 읽기 항목은 미실행, 수정·복원은 API 기록 없음, 엔진 항목은 엔진 확인 필요로 구분합니다. 기록에 성공 문구가 있어도 심판 통과 증거가 아닙니다. 전체 41종의 공식 명세/결과 수신 인터페이스가 없어 모든 종별 집행 결과는 미실행으로 둡니다. 실제 엔진 탐지 사건 수·회수 수·회수 시간은 null/미실측으로 표시합니다.

DB에는 가린 경로·HTTP 상태·기대 상태·시각·요청 UUID·상세 검증 boolean/고정 오류 코드만 추가합니다. owner_id는 본인 기록을 필터하는 서버 전용 연결값이며 화면/내려받기에는 포함하지 않습니다. 메모/백업 ID·메모 본문·실명·키·토큰·해시 값은 점검 기록에 남기지 않습니다. 직접 anon/authenticated SELECT/INSERT 권한은 없으며 service_role만 SELECT/INSERT 합니다. UPDATE/DELETE는 트리거로 거부합니다.

## 중지와 복구

로그아웃/앱 승인 철회로 보호 요청을 중지하고 기록을 지우지 않습니다. 정책 복구는 사전 검증한 policy-9의 제한된 시험 파일만 격리 폴더에서 수행합니다. 실제 B 메모 복구에는 검증한 backupId·confirmHash와 명시적 사용자 승인 절차가 필요합니다. 복원 API/기존 감사 이력은 변경하지 않았습니다. 다른 계정 자료·정책·감사는 복구 범위에 넣지 않습니다.

## 보완된 실행 방법

점검 선택에는 12개 항목을 모두 표시합니다. 메모 수정은 기존 메모 편집기로 이동하고 저장하면 자동 기록합니다. 공지 수정 거부는 notices의 실제 ID에 빈 PUT 본문을 보내 학생의 강사 권한 거부를 검사합니다. 빈 본문은 강사에게도 검증 오류이므로 공지 내용을 수정하지 않습니다. 복원은 B의 기존 사전 백업을 GET으로 먼저 검증하고, 대상·해시·변경 범위 표시 뒤 사용자가 동의해야 POST를 보냅니다. 복원 뒤 자동 GET 재검증으로 현재내용일치를 기록합니다. 선택/ID 변경·로그아웃·오프라인 잠금 때 복원 확인 정보를 지우며, 새 계정에 이전 확인을 재사용하지 않습니다.

추가 SQL은 기존 append-only 기록의 case/method/route/source 허용 목록만 확장합니다. 기존 행과 변경 방지 트리거를 보존합니다. vault_ops_restore_summary는 서버가 검증한 actor UUID로 필터한 operation/at 최근 50개만 반환하며 일반 클라이언트는 호출할 수 없습니다. vault_ops_capabilities가 2를 반환해야 화면에서 새 점검을 실행합니다. 키와 권한 규칙, 8시간 확인 시간은 바꾸지 않습니다.

확인 명령: npm run test:campaign. 운영 SQL 적용 및 새 수정·복원 실측은 사용자 실행 전까지 미확인입니다. 과거 읽기 기록과 사용자 보고를 새 실행 결과로 복제하지 않습니다.
